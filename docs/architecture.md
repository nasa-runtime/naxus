# 仓库身份、运行与持久化

Naxus 通过 NASA Application 拥有一个常驻进程、一个 HTTP listener 和统一停机权威。YAML、文件日志、口令密码学、浏览器身份接口、授权快照及指标目录复用 NASA。SQLite、Cargo 协议、制品缓存、工作区编排和 Admin 状态由 Naxus 定义，不依赖外部数据库或注册中心。

当前依赖的 NASA SQL 能力面向 MySQL/PostgreSQL，没有 SQLite 适配器。Naxus 使用 rusqlite 的本地连接、WAL/FULL 和 backup API，将账号权限与仓库状态保存在同一数据库事务中；本地运行和远程部署均无需另设数据库服务。

## 四种身份

逻辑坐标由仓库、Cargo 名称与 SemVer 组成。原始包体 SHA-256 表达字节身份；修订另存完整索引、元数据摘要和发布主体；快照固定一组修订及父关系；HEAD 只是当前选择。

`mutable` 允许同坐标的新内容在新快照生效。`immutable` 保持既有字节及依赖语义，yank 状态只影响新快照。历史快照均不可变。服务、hosted 和 proxy UUID 在重启及备份恢复时保持稳定。

## 提交顺序

```text
原始流 → 同盘 staging → 大小/容量/SHA-256 → 文件同步
                                                  ↓
                                    objects/sha256 + 目录同步
                                                  ↓
SQLite：对象代次 → 修订 → 快照 → 批次终态/幂等/审计 → HEAD
                                                  ↓
                                            事务提交成功
```

网络流不持有对象生命周期门禁；只有校验完成的安装才进入门禁。正式对象先持久化，数据库事务才能引用。提交前退出可留下未引用对象，不会公开缺字节快照。预期 HEAD 阻止并发覆盖其他提交，幂等身份绑定仓库、主体、原预期 HEAD 和完整内容。

归档只做静态有界读取，不在服务端解包执行。Cargo 发布 JSON 与规范化 manifest 的名称、版本、依赖别名、kind、target、来源、feature、links 和 MSRV 需要一致。工作区批次在固定快照叠加本批次全部替换后的最终视图内检查私有依赖闭包；被覆盖的旧条目不能满足新依赖，全部成员一起可见。

归档、声明长度、发布元数据和依赖来源均在私有暂存文件上验证，通过后才安装正式对象。无效上传不会获得一小时未发布对象宽限；宽限只用于已经完整安装但尚未形成发布引用的有效对象。

归档、原生发布 JSON 和代理索引共同检查 Cargo 已知的 `public`、`artifact`、`bindep_target`、`lib` 字段类型。当前不支持 artifact 或 `public = true`，声明这些语义会被拒绝；普通依赖的中性默认值仍可使用。manifest 依赖项内的 `target` 是 artifact 构建目标，不能与外层平台条件表混淆。未知未来字段不按全局白名单拒绝，也不作为新增语义已受支持的证明。

原生发布与显式批次共用提交错误分类：归档或发布元数据无效为 422，私有依赖闭包、HEAD、幂等键及仓库策略冲突为 409，授权失效为 403，容量门限不足为 507。发布路径以 `RepositoryFailure` 的变体识别状态、授权和容量拒绝；包名或诊断文字不参与这些分类。

扩展接口在纯输入校验通过后才执行存储动作；store 使用 `RepositoryFailure::InvalidRequest`、`NotFound`、`Conflict`、`Forbidden` 及容量分类保留领域语义，附加 context 不改变分类。协议层不解析诊断字符串；无效输入为 400，资源缺失为 404。session 与租约的未知、过期、跨主体或跨来源/仓库访问统一按不存在处理；失败续期不能延长任何保护期限。租约释放保持幂等，未匹配记录也返回空成功响应。

Admin 对仓库名称完成授权解析后使用稳定 UUID 执行查询，未知资源与越权分别保留 404、403；真实存储故障不伪装成权限拒绝。管理和扩展错误体共用 `code`、安全 `message`、`request_id`，关联 ID 取自 NASA 请求扩展并在异步请求作用域内保持不变，正文与响应头一致。管理边界也将框架参数、方法拒绝转成同一合同，不回显原始输入；浏览器认证不声明 Cargo challenge。

管理输入在 store 边界按领域类型分类：名称、版本、游标、能力组合及跨仓快照选择无效为 400，token 扩大账户仓库范围为 403，重复用户名、不可保留的已撤销历史和清除保护阻挡为 409，管理选集预算不足为 429。内部历史链损坏、对象完整性或数据库故障仍属于依赖失败，不能因管理请求可达而归为输入无效。管理前缀的显式兜底覆盖未知页面、API 及 API 前缀本身，经过相同的同源、安全头和请求 ID 边界后返回 404；registry 认证边界不承接管理路径。

浏览器收到 401 后先撤销旧身份请求的发布资格，再停止轮询、取消在途请求并重建登录页；取消前已缓冲的响应也不得恢复旧页面。重新认证后重新读取角色和仓库范围。403 只拒绝本次操作；有效会话的 CSRF 拒绝不应被当作会话失效。启动时的 503、无效响应和网络故障显示不可用状态，并提供重新连接。

## 快照与客户端

提交记录变更集及逻辑移除标记，最长每 32 层创建同语义检查点。完整映射与完成标记一起提交。父链读取有深度、循环和仓库归属检查。

`cargo naxus` 在工作区独占权内创建临时 Cargo 配置和锁文件；固定 hosted 快照，保持独立公开来源身份，调用原生 Cargo 解析及校验真实图。私有依赖使用实际修订 ID 与数据/元数据摘要；公开集合在服务端完整物化后才提交关联双锁。

发布前将固定归档、服务/仓库/主体身份、预期 HEAD、创建请求摘要和幂等键持久化到独立发布日志。日志先于任何远端写入公开；中断后只恢复原批次和原字节，不重新打包现有源码。提交不确定时保留现场，明确终态先保存收据再清理；显式终止未提交发布不会删除已提交制品。

单批次最多 4096 个条目，完整索引条目 JSON 数组最多 32 MiB；服务端按 UTF-8 原始字节及数组分隔符在登记事务内累计裁决，超限不改变已有条目和 HEAD。客户端发布日志最多 32 MiB，超限在首个远端写入前拒绝。批次创建、上传回执和所有终态回读使用 32 MiB 加 64 KiB 响应预算，为有界身份、状态和期限字段留出空间；其他控制 JSON 仍限制为 16 MiB。提交后恢复和明确终止不会因使用普通控制响应上限而失去可达性。

固定批次大小超限通过 `PublishBatchTooLarge` 映射为 HTTP 413、`batch_too_large`；受管资源配额通过 `ResourceLimitExceeded` 映射为 429。分类不依赖诊断文字。413 保留旧日志与已接受集合，用户明确终止旧意图后缩小输入；客户端不会自动换键重发或把该输入当作可恢复限流。

依赖 target 在可见前执行 Cargo 同源语法解析；单项最多 16 KiB，字符串外括号最多嵌套 64 层。无递归预扫描先限制结构深度，再进入递归解析与析构，防止不可信表达式耗尽服务调用栈；实际目标匹配继续由 Cargo 完成。

双锁不是两次改名即原子：新旧材料与摘要先同步，恢复日志先公开，再依次替换两个文件。中断后完成同一新状态，或在新材料不足时回滚已验证旧状态；发现未知外部编辑则拒绝覆盖。业务源码和 manifest 不参与快照来源改写；全局 Cargo 缓存不被直接删除或篡改。

新建客户端私有目录时先同步目录及其父目录，再公开恢复日志；服务端同样先持久化新数据根的目录链，再写入稳定身份。两类私有目录在 Unix 上使用 0700，并拒绝末级目录为符号链接。

在线构建取得十分钟租约，每分钟续期并在退出时释放。失去持续保护后拒绝报告成功或提交新双锁；异常进程由服务端到期回收。离线构建仅使用本机缓存，不声称持有服务端租约。

取得租约守卫前，客户端核对请求仓库、完整坐标多重集合、固定快照全部字段，以及每个修订的坐标、归属和元数据摘要。续期响应同时证明租约、仓库、快照和 `snapshot_set_id`，不能把另一份保留权误认为本次构建已受保护。

## 公开代理

一个 proxy 对应一个独立逻辑 registry。物理镜像按配置顺序回源；条件请求证据绑定精确镜像地址，不跨镜像借用 ETag 或 304 正文。JSONL 与 `.crate` 原始字节保持不变；已知坐标的 checksum 变化被拒绝。

已有代理按 `registry_identity` 比较配置来源。等价 URL 写法可用于重启，数据库中的 UUID 和最初原始声明继续保留，客户端仍从持久映射取得来源；真实来源身份改变时拒绝启动。

缓存替换前校验索引 schema、MSRV、依赖声明及本 crate 的 feature 图，包括隐式可选依赖、显式 `dep:`、强弱依赖 feature 引用和两个 feature 字段的合并。合法循环可以保留；依赖包是否实际提供被请求的 feature 仍由 Cargo 解析完整依赖图。公开版本保留合法 build metadata，不套用 hosted 坐标策略。标准 crates.io Git/sparse 别名在配置、发布和跨 registry 路由中使用同一比较身份，其他 registry 保留 Git/sparse 协议差异；规范身份重复时拒绝配置，sparse 原始声明缺少末尾斜线时拒绝而不静默补全。

解析 session 首次读取某名称后固定其原始索引，其他请求刷新缓存不改变已固定视图。镜像版本缺口通过新 session 完整图重试处理，最多六十四个镜像组合；不修改原 session，不合并多份索引，也不解析 Cargo 非结构化错误文本推断版本要求。

每个解析视图失败时，客户端输出该次 Cargo 失败诊断；后续视图的缺包错误不能掩盖先前的下载或回源失败原因。

回源使用独立预算、固定数量互斥分片和整体期限。每次 DNS 与重定向重新验证来源，固定已核验连接地址，不继承环境代理或业务认证头。默认只允许公网地址及声明来源。持久包体按摘要复用；索引新鲜度和包体缓存独立观察。

同一类型化回源策略覆盖索引、下载配置和包体。404、网络可用性失败及 5xx 允许切换；401/403、TLS 身份、响应结构、来源或摘要冲突停止。429 保存该配置上游的有界单调时钟冷却并继续下一镜像，冷却期间三个阶段都不发请求；状态仅在进程内保留。未分类失败默认停止，不能把未知完整性错误当作可用性失败。配置位置限定冷却和指标的数量，不按 crate 或 URL 响应动态扩张。配置、错误码和指标含义见[配置说明](configuration.md)。

## 清除与恢复

Admin 写操作在最终数据库事务内复验账号的启用状态、口令与授权代际、角色和仓库范围。排队中的旧请求不能在账号换密或授权变化后借用新的权限完成操作。

逻辑移除仅影响后续可见映射。物理清除预览固定精确坐标、历史撤销意图、对象代次、共享引用、保护阻挡和可回收字节；提交复验同一指纹及当前权限。

持久删除权威先提交，再移动正式文件到任务私有 trash，核验并移除字节，同步目录后记录 purged 和实际释放空间。旧任务只能处理原代次。共享有效引用保留字节，活动读者及构建租约阻止受理，已撤销历史返回 Gone。公开缓存清理只移除来源缓存与物化证据，不创建名称或版本封禁。

Cargo 下载模板绑定名称、版本、摘要，历史模板还绑定快照。通用摘要路由表达“同仓任一仍有效正式引用”：仍有共享引用即可读取，仅剩撤销引用时返回 Gone。它不代替精确修订地址；引用核对和读取登记在同一对象门禁内完成。

启动先恢复已受理清除，再检查完整性。只有同代次清除证据能解释合法对象缺失；其余丢失、错误摘要或归属不一致都拒绝就绪。维护任务有界清理短期记录、checkpoint WAL、观察容量并轮转核验对象。清除失败保留阶段和安全错误类别，退避后续试，不永久占据任务队列。

## 存储和备份边界

进程内路径门禁和操作系统锁共同保证一个数据根单写入者。支持本地 ext4/XFS/Btrfs/F2FS/overlayfs、APFS/HFS+，拒绝网络、未知和宿主共享数据文件系统。客户端事务采用相同本地持久化门禁。

备份同时取得对象和数据库一致视图，使用 SQLite backup API 和独立文件副本。恢复在新目录核验清单、对象及全部数据库引用，再公开目标；保留服务与仓库身份。命令行路径要求服务停机，不提供在线恢复覆盖。

一个节点重启期间允许短暂不可用。此架构不提供分布式多写、跨节点共识、透明故障转移或零中断升级。
