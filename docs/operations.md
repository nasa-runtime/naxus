# 运行与维护

`naxus serve` 保持前台运行，由 systemd、launchd 或容器负责开机启动和异常重启。服务不依赖业务构建进程。Admin 与 registry 共用配置中的一个端口。

## 数据与访问

原生默认数据根为 `~/.naxus/repository`，容器使用 `/var/lib/naxus`。数据根包含 SQLite、完整对象、暂存、清除任务证据和可能存在的首次引导口令。只允许服务账号及备份运维读取，不要暴露为静态 Web 目录。一个数据根只允许一个活动实例。

数据根必须归运行账号所有。Unix 上程序将数据根设为 0700，新建的父目录也使用 0700；末级数据根不能是符号链接。挂载已有数据卷或使用自定义 UID 时，先由运维配置正确所有权，只有组写权限不足以满足该合同。

Linux 使用 ext4、XFS、Btrfs、F2FS、overlayfs；macOS 使用 APFS/HFS+。NFS、SMB、内存盘和 Docker Desktop 宿主共享挂载不在持久化支持范围内。网络服务入口可以远程访问，数据根必须满足本地存储合同。

远程部署使用 managed 认证和 HTTPS 反向代理。代理需支持大包上传、至少 130 秒回源等待和优雅连接结束；上传限制应大于业务允许的完整协议帧。对 `/admin/`、健康和指标路径按部署网络限制访问。不要由代理缓存认证错误或私有 registry 正文。

## 健康和观测

```sh
naxus healthcheck
naxus healthcheck --url http://127.0.0.1:7443/readyz
```

`/livez` 表示进程存活，`/readyz` 表示受管读取依赖可用。低容量通过写入贡献单独表达，不应让已缓存读取一同失去就绪。上游不可用会影响新内容或显式刷新，不会自动撤销已缓存图。

`/metrics` 由 NASA 的唯一进程指标目录输出，包含公开索引/包体缓存命中、实际回源请求和读取字节、清除失败次数、空闲/保留空间及写入可用状态。指标不使用任意包名、用户或 URL 作为标签。计数器在进程重启后重新累计；持久审计与任务状态保存在数据库。

日志路径为 `${NAXUS_LOG_PATH:/usr/local/logs/${application.name}}`，默认单文件 100 MB、总容量 1 GB、保留七天并拆分错误日志。环境变量指定路径须提前授予运行账号写权限。

Admin 错误提示附带请求 ID，与错误正文 `request_id` 和 `x-request-id` 响应头一致，可用于关联日志。仓库不存在为 404，无权访问为 403；认证、CSRF、来源拒绝、校验、冲突、限流及依赖不可用均有固定 `code`，不会向页面返回 SQL、口令或内部路径。

非法用户名、包名、版本、游标或 token 能力组合返回 400；扩大 token 仓库范围返回 403；重复用户名、包含已撤销修订的快照保留请求和清除引用阻挡返回 409。应调整输入、授权或保留范围后重新操作，不按 503 重试。未知管理地址返回 404，不要求 Cargo 凭据；写请求仍需满足同源检查。

账号换密、停用、授权变化或会话到期后，下一次未授权请求会使页面停止轮询、清空旧身份及导航并显示重新登录入口；403 操作拒绝保留当前登录。初次连接遇到服务不可用或网络故障时显示“仓库服务暂不可用”，恢复后点击“重新连接”，无需把依赖故障当作口令错误处理。

## 停机、备份和恢复

SIGTERM 由 NASA 接收并执行受管停机，停止接收新增写操作，等待有界工作达到持久边界。容器停止宽限应大于应用的 60 秒停机预算。

命令行备份要求先停服，通过数据根独占锁验证没有活动实例；不是直接复制 SQLite 主文件。备份使用 SQLite 一致备份 API，再保存独立对象副本和带摘要的清单。

```sh
naxus backup --data-dir /var/lib/naxus --output /backup/naxus-saved
naxus restore --backup /backup/naxus-saved --data-dir /var/lib/naxus-restored
```

目标目录须不存在，父目录须已经建立且可写。不能将备份写入源数据根。恢复先在同文件系统暂存根核验数据库、全部引用和对象，再原子公开新数据目录。身份、仓库 UUID、快照、用户、token 与历史撤销保持原值；外部 YAML、TLS 和单一 token secret 文件需另外备份。

备份包含账号散列及可能存在的一次性引导材料，应使用受限访问、加密存储和独立保留策略。对象采用实体副本，不与线上数据共享硬链接。空间不足、摘要不一致或已有目标目录会明确失败。进程被强制终止可能留下同父目录内 `.naxus-backup-<UUID>` 未完成暂存根；确认对应操作已结束且路径精确后方可人工移除。

备份清单上限 64 MiB，创建和恢复使用同一限制；超限时不公开不可恢复的备份目录。数据库、对象和引导材料均使用受限文件权限。

恢复到新数据根后，使用原规范对外 URL 启动并检查 readiness。不要删除旧数据根来覆盖恢复目标。升级前保留完整备份，旧程序不能打开它不认识的新 schema；回退通过对应旧版本及升级前备份完成。

## 平台托管

Linux 可使用 [systemd 单元](../deploy/naxus.service)，按实际安装路径修改用户、配置和可写目录。不要同时让 systemd 与手工进程争用数据根。

macOS 可由 launchd 的 `ProgramArguments` 指向 `naxus serve --config <绝对路径>`，设置 `RunAtLoad`、`KeepAlive`、`WorkingDirectory` 以及 `NAXUS_LOG_PATH`。数据使用本机 APFS，进程保持前台。launchd 配置中的环境变量不应写入实际 Cargo token。

## 清除与容量

Admin 中先预览精确来源和版本范围，再提交已经固定影响的动作。逻辑移除与 yank 不释放空间。物理清除只有持久任务完成后才确认实际释放字节；共享引用会使可回收空间小于包大小。任务失败保留原代次与阶段，按退避继续，也可由有权限运维明确重试。

HEAD、保留点、有效构建租约及活动读者不会被强制跨过。历史被主动永久撤销后固定读取返回 Gone；重新上传相同摘要不会恢复已撤销修订的读取权限。公开缓存清理允许同版本及未来版本重新回源，不等同于封禁。

在 Admin 的快照保留页固定需要保留的快照，并记录业务原因；释放保留点只解除保护，不删除制品。逻辑移除后可从历史中明确选择未撤销修订恢复。修订历史和审计均从最新记录向前分页，账号授权变化与任务重试均留存。

上传完成但未形成任何发布或公开引用的对象，经过一小时宽限后由持久任务分批回收；开放批次、下载和解析 session 阻止回收。已发布的历史对象不会因该宽限自动删除。正式对象安装与登记间发生中断时，启动会校验字节并恢复登记，随后仍遵守相同宽限。

磁盘保留门限默认 2 GiB。容量不足时先处理日志、独立备份或通过 Admin 清理明确不再保留的内容，不能直接删除 objects 或修改数据库。未授权的对象缺失会导致启动或完整性检查失败。
