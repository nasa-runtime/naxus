# 常见问题与支持

## 版本不变，但消费者没有得到新内容

确认使用 `cargo naxus build`、`run` 等入口。普通 Cargo 使用不可变 registry 缓存；`--locked` 则有意保持原修订。生产者还需要同版本覆盖权限，且发布必须完成提交。不要删除 Cargo 全局缓存来强行改变已有内容身份。

默认构建保持已选 SemVer。需要版本升级时执行 `cargo naxus update`；只更新同版本内容则执行默认命令。客户端命令与双锁含义见[客户端说明](client.md)。

## 401、403 与 404

401 表示身份失效。账号换密、停用或授权变化会撤销旧会话和 token；Admin 返回登录页，客户端需要新的有效 token。

403 表示当前操作、仓库范围、Origin 或 CSRF 不允许。read token 不能发布；publish token 默认不允许覆盖；token 不能扩大所属账号的仓库范围。浏览器 Cookie 不能用于 Cargo 认证。

404 表示目标不存在或访问了未知管理路径。检查仓库名称/UUID、快照、修订与规范路径前缀。未知管理地址不要求 Cargo token。完整状态合同见[HTTP 接口](protocol.md)。

## HEAD、保留点或清除冲突

409 的 HEAD 冲突表示预览或发布基于旧视图，不能改成新 HEAD 后复用旧意图。管理操作应重新预览；客户端按已保存发布日志确认原批次终态，再开始新发布。

物理清除被 HEAD、显式保留、活动租约或下载读者阻挡时不会受理任务。先明确是否仍需要这些内容，再解除相应引用。包含已撤销修订的快照不能通过新保留点重新开放；精确历史访问的 410 也不会因重装相同摘要而取消。

## 413、429 与磁盘不足

413 要求减少包体、条目数量或元数据大小。已有未完成发布先执行 `cargo naxus publish --abort-pending`，不能通过换幂等键或删日志绕过原意图。

429 表示认证或仓库受管配额不足。上游 429 的 Retry-After 则触发对应物理上游的有界冷却，并允许后续镜像，不能把它缓存为不存在。

507 表示数据卷低于保留门限。先处理日志和备份，或通过 Admin 清除确实不再需要的内容。已发布历史不会因上传宽限自动淘汰；不能直接删除 objects 或修改 SQLite。低容量不应阻止已有完整对象读取。

## 上游失败与离线构建

上游 401/403 通过 502 及 upstream_unauthorized / upstream_forbidden 报告，检查镜像访问条件。TLS、来源、响应结构和 checksum 冲突会停止回源，不通过其他镜像掩盖。

`--locked --offline` 需要完整双锁和本机 Cargo 缓存，并且没有未完成发布。离线成功不能证明远端历史仍然可用，也不会持有服务端租约。重新联网时继续复验服务与物化身份。

## 容器无法写入或服务拒绝启动

数据根必须归运行账号所有，Unix 权限为 0700；默认镜像用户是 10001:10001。Docker Desktop 使用 Linux 原生 named volume。自定义 UID、宿主挂载与恢复目录的要求见[容器说明](../docker/README.md)。

一个数据根只允许一个活动实例。原生数据根末级符号链接、网络文件系统、内存盘和宿主共享挂载不满足持久化合同。无法解释的对象丢失或摘要不符会阻止就绪；从完整备份恢复，不创建空文件补足引用。

日志目录也须可写，表达式为 `${NAXUS_LOG_PATH:/usr/local/logs/${application.name}}`。本机用户设置 NAXUS_LOG_PATH 为自己可写的目录。完整备份、恢复与升级流程见[运行维护](operations.md)。

## 诊断信息与支持渠道

公开使用问题通过 GitHub 仓库的 Issue 提交，先搜索已有条目。提供组件版本、Rust/Cargo 版本、OS/CPU、原生或容器部署方式、脱敏配置、重现步骤、预期与实际结果，以及错误 code/request_id。镜像部署同时提供不可变镜像 digest 和源码标识。

不要上传实际 token、Cookie、CSRF、引导口令、私有制品、原始数据库或未脱敏日志。安全问题使用 [SECURITY.md](../SECURITY.md) 的私有渠道，普通 Issue 不适合作为敏感报告入口。

项目通过公开 Issue 和贡献流程协作，不承诺商业 SLA、特定响应时间或代管私服数据。
